# Docker images for the fork

## Layout

- `Dockerfile.base` — shared base image with all runtime deps (CUDA, vLLM, transformers, claude-code, etc.). Built once, pushed to Docker Hub, reused across every (benchmark, model) combo.
- (per-task Dockerfiles are generated by `src/harbor_adapter/run_adapter.py`; see "Per-task images" below.)

## Build + push the base

```bash
# Login (one-time per machine)
docker login

# Build for RunPod's linux/amd64 from any host, push to Docker Hub
docker buildx build \
    --platform linux/amd64 \
    -f dockerfiles/Dockerfile.base \
    -t jackpayne123/ptb-base:1 \
    --push \
    .
```

First build: ~10-15 min (CUDA layer + python deps + npm). Push: 2-5 min depending on link.

## Per-task images

The Harbor adapter (`src/harbor_adapter/template/environment/Dockerfile`) is patched to derive from this base — only the `COPY . /home/agent/workspace/` and `chmod` lines remain in the per-task layer. Building a per-task image takes ~5s after the base is cached.

## Adding a new safety benchmark

1. Add `src/eval/tasks/<benchmark>/{evaluate.py, benchmark.txt, ...}` mirroring PTB's existing tasks.
2. Add an entry to `BENCHMARKS` in `src/harbor_adapter/adapter.py`.
3. If the benchmark needs extra Python deps not in the base, add a `RUN pip install ...` line to the per-task Dockerfile (not the base — keeps the base small).

No base-image rebuild is needed for new benchmarks unless they need new system-level deps.

## Versioning

Tag base images monotonically (`:1`, `:2`, ...) and never mutate `:1` after push — pinning by tag is the contract. Use `latest` only for development.
